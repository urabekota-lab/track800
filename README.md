# Track800

800m を主戦場にする選手・指導者のための練習アプリ。
練習を記録すると、そこから **いまの 800m の推定タイム** を出し、
その数字を基準に **練習メニューの設定タイムを自動計算** します。

- 練習ログの記録（1本ごとのタイム）
- 過去の練習の振り返り（月ごとの履歴 / 距離別の伸び / 推移グラフ）
- いまの練習内容からの 800m 推定タイム
- 推定タイムに合わせたペースゾーン・レース通過・換算タイム
- 時期／種類に応じた練習メニューの提案（1回分・1週間）
- 練習メニューの作成
- 共有コードによるメニューの受け渡し
- データの書き出し・取り込み

技術スタック: Expo SDK 57 (React Native 0.86 / React 19.2)

**スマホ（iOS / Android）がメインの実行環境**です。Web でも動きますが、
レイアウトはスマホの画面幅を前提に組んでいます。

## サーバーを使いません

データはすべて端末の中だけに保存されます。
アカウント登録もログインもなく、開いた瞬間から使えて、オフラインでも動きます。

そのかわり次の割り切りがあります。

- 端末をまたいだ自動同期はありません（書き出しファイルで移します）
- 不特定多数の公開メニューを検索・閲覧する機能はありません（共有はコードの受け渡しです）
- **アプリを削除するとデータも消えます。**「設定」から定期的に書き出してください

## セットアップ

環境変数の設定は不要です。

```bash
npm install
```

**スマホ実機で動かす（メインの使い方）**

1. スマホに **Expo Go** をインストール（App Store / Google Play）
2. PC とスマホを**同じ Wi-Fi** につなぐ
3. PC で起動して、表示される QR コードをスマホで読み取る

```bash
npx expo start
```

> iPhone では **標準のカメラアプリ**で QR を読みます。iOS 版 Expo Go には
> QR スキャナーがありません（Android 版にはあります）。
>
> Expo Go は**最新 SDK 版しか動きません**。「このバージョンに対応していない」と
> 言われたら、Expo Go を更新するか、プロジェクトの SDK を上げてください（AGENTS.md 参照）。

同じ Wi-Fi につなげない場合はトンネル経由で:

```bash
npx expo start --tunnel
```

**PC のブラウザで確認する**

```bash
npx expo start --web --port 8084
```

## メニューの共有（共有コード）

サーバーを持たないので、メニューは**文字列**として受け渡します。

**送る側**: メニューを開いて「共有コードを送る」
→ 共有シートが出るので LINE などで送る（Web ではコードが画面に出ます）

**受け取る側**: 「メニュー」タブ → 右上の取り込みボタン
→ 届いた `T800…` を貼り付けて「取り込む」

コードは 700〜1000 文字ほどです。メニュー名・説明・全セット・設定タイム・レスト・
メモまで全部入っています。読む必要はないので、そのまま送ってください。

仕組みは [`lib/shareCode.ts`](lib/shareCode.ts):

- メニューを短いキーの JSON にして UTF-8 → 独自の 64 進表記へ
- 距離から自動生成できる見出し（`400m × 5`）は送らずに復元する
- 末尾にチェックサムを付けて、途中で欠けた貼り付けを検出する
- 取り込み時は改行や空白を落とすので、メッセージアプリを経由しても読めます

## データの書き出し・取り込み

「設定」→「データの書き出し・取り込み」から、全データを1つの JSON ファイルに
書き出せます。機種変更やアプリ削除への備えです。

- ネイティブ: 共有シートが開くので「ファイルに保存」やクラウドへ
- Web: そのままダウンロード

取り込みは**既存データをすべて置き換えます**（確認ダイアログが出ます）。
手で編集された壊れた値は、既定値に寄せるか除外して読み込みます。

## 練習の記録

グラウンドで片手で入れることを前提にしています。

- **前回と同じ** — 直近の練習と同じ距離・本数・走り方を復元します（タイムは空）。
  大学は同じメニューを繰り返すので、これが一番速い入口です
- **メニューから開く** — 「この練習をやる」なら距離も本数も設定タイムも入った状態で始まります
- 入力欄に仮の値は入れていません。空から始めて、必要な数だけ「1本足す」で増やします
- **読み取り結果をその場で表示** — `62.5` `1:02.5` `1'03` のどれで入れても、
  右側に `1:02.50` と解釈結果が出ます。読めない入力は赤で「読めません」
- **合計距離をリアルタイム表示** — 見出しに「5本 ・ 合計 2.0km」と出ます
- **任意項目は畳んである** — レスト・コンディション・メモは必要なときだけ開きます

## メニュー結果の分析

メニュー詳細の「この練習をやる」を押すと、**設定タイム入りで記録画面が開きます**。
保存すると、各本が設定に対してどうだったかが自動で分析されます。

| 指標 | 意味 |
|---|---|
| **落ち込み** | 最終本と1本目の差。800m は最後まで押せるかで決まるので最重要 |
| ばらつき | 本数間の標準偏差。ペース感覚の精度 |
| 設定達成 | 設定以内で走れた本数 |

各本には設定との差（`+3.0` など）が並び、総評が付きます。

- 落ち込み 4% 以上 → 乳酸耐性の不足として警告
- 設定より 1.5秒以上速い → **「狙った刺激から外れている」と警告**
  （設定より速く走ってしまうのは大学生に多い失敗）

設定タイムは記録側（`WorkoutRep.target`）に保存しています。
あとでメニューを編集しても、そのとき狙っていた設定が残るようにするためです。

## 目標レースと時期の自動判定

「設定」でレース日を入れると、そこまでの週数から時期が決まります。
手で時期を選ぶ必要はありません（[`lib/analysis.ts`](lib/analysis.ts) の `seasonInfo`）。

| レースまで | 時期 |
|---|---|
| 16週以上 | 準備期 |
| 8〜16週 | 鍛錬期 |
| 3〜8週 | 仕上げ期 |
| 3週以内 | 試合期 |

ホームにカウントダウンが出て、「提案」タブの時期も自動で合わせます。

## 過去の練習を振り返る

「記録」タブは3つの見方を切り替えられます。

**履歴** — 月ごとにまとめた練習の一覧。各月の回数と総走行距離、
1回ごとの全本数のタイム（その日の最速は色付き）とメモが見られます。

**推移** — 同じ距離のセッション平均を並べた棒グラフ。速いほど棒が高くなります。
初回からの短縮量も出ます。

**距離別** — 距離ごとの回数・本数・最速・直近の平均と、前回との差。
行をタップすると、その距離を走った練習が全部並びます。

### 推移に「800m 推定タイム」を使っていない理由

当初は「その日までの記録で 800m 推定を出し直す」方式で作りましたが、**誤解を招くので
やめました**。推定に使えるモデル（400mから／距離換算／CSモデル）が時期によって増減するため、
実力ではなく「記録の構成の変化」がグラフに出てしまいます。

実際、400m が 64.5 秒→62.1 秒と**速くなっている**データで試したところ、
グラフは「＋11.2 秒 遅くなっています」と逆を示しました。
序盤は 400m のベストだけなので速い推定が出て、あとから 600m や 1000m の
練習ペースの記録が入ると推定が下がる、という理屈です。

同一距離どうしの比較なら換算もモデル選択も挟まらないので、素直に速さの変化が出ます。

## 推定タイムの考え方

「なんとなくの目安」ではなく、根拠の異なる3つのモデルを重み付けして混ぜています。
ホーム画面ではどのモデルが何秒を出し、何%寄与したかを全部表示します。

### 1. Critical Speed モデル（[`lib/pace.ts`](lib/pace.ts)）

距離の違う全力相当の記録から `D = CS·t + D'` を最小二乗フィットし、`t₈₀₀ = (800 − D') / CS` で予測します。

- **CS**（Critical Speed）= 有酸素的に維持できる速度
- **D'** = それを超えて使える「距離の貯金」

このモデルは概ね 2〜15 分の全力持続に対して線形になる前提なので、
**600m 未満の記録は入れていません**。400m を混ぜると CS が過大・D' が過小に歪みます。

### 2. 400m からのスピードリザーブ方式

`800m ≒ 400mPB × 2 + K`。上乗せ分 K はカテゴリと選手タイプで変わります
（スピード型ほど大きく、持久型ほど小さい）。

### 3. 距離換算

各記録を実測ベースの距離比テーブルで 800m 相当に換算し、
**800m に距離が近い記録ほど重く**平均します。

Riegel 式（指数 1.06）は 800m と 1500m の間では実測と合いません
（実際の 800/1500 比から逆算すると指数は約 1.19 になります）。
そのため短中距離では指数式ではなく実測ベースの比を使っています。

### 練習の1本を「単発全力」に換算する

レストが短いほど、同じ力でもタイムは遅く出ます。
記録画面で選んだ「走り方」に応じて、単発全力相当へ割り引いてからモデルに渡します。

| 走り方 | 係数 |
|---|---|
| レース / TT | 1.00 |
| レペ（完全回復） | 0.97 |
| インターバル | 0.90 |
| 連続走 / 変化走 | 0.85 |

**この係数は当初 1.5% 引き程度に設定していましたが、明確な誤りでした。**
インターバルや連続走は設定ペースを守って走る練習で、全力ではありません。
それをほぼ全力として扱っていたため、**練習を記録するほど推定が遅くなる**という
おかしな挙動になっていました（400m ベストだけなら 1:58 だったのが、
600m と 1000m の練習を足すと 2:09 まで下がる）。

実勢の目安として、2:00 の選手は 600m×4 を 1:32〜1:38 で回しますが、
単発全力の 600m は 1:25〜1:26 です。比は約 0.90。ここを基準に置き直しました。

修正後は記録が増えるほど推定が収束し、精度も上がります。

| 記録 | 修正前 | 修正後 |
|---|---|---|
| 400m ベストのみ | 1:58 | 1:57.0（精度44%） |
| ＋600m 練習 | 2:02 | 1:59.5（精度56%） |
| ＋1000m 練習 | 2:09（悪化） | 2:00.6（精度73%） |

経験則ベースの係数です。本数やレストの長さで実際は上下するので、
これに頼る推定は信頼度を下げています。

### VDOT について

VDOT は Daniels 自身が 1500m 未満では信頼できないとしているため、
**800m の予測には使わず**、1500m 以上の記録があるときの持久力の指標として表示するだけにしています。

### 短い距離からは推定しない

**400m 未満の記録しかない場合、800m の推定は行いません。**

150m や 300m のタイムが表すのは主に無酸素的なスピードで、800m を走り切る力とは
別物です。ここを一緒に扱うと、150m のペースをそのまま引き伸ばした
1:34（世界記録より速い）のような値が出てしまいます。

- 換算に使うのは 400m 以上の記録だけ（`PREDICT_MIN_DISTANCE`）
- 重みづけ（`closeness`）は短い側の減衰を長い側より強くしている。
  600m や 1000m は 800m を語れるが、400m 付近はスピード寄りなので効きを下げる
- 短い記録しかないときは、数字を出す代わりに「何を測れば推定できるか」を案内する

### 現実的でない値で止める

入力ミスや極端な記録で推定が暴走しないよう、カテゴリ別の下限を置いています
（`PLAUSIBLE_FLOOR`）。800m の世界記録は 1:40.91、日本の高校記録は 1:46 前後、
中学記録は 1:53 前後なので、それを踏まえた値です。

| カテゴリ | 下限 |
|---|---|
| 中学生 | 1:52 |
| 高校生 | 1:44 |
| 大学生・社会人 | 1:41 |

下限で止めた場合は、黙って書き換えずに「計算上は○○だが現実的な範囲を超えているので
止めている」と表示し、精度も 15% 以下に落とします。予測レンジの下端も下限より速くなりません。

### 精度表示

「800m にどれだけ近い距離の記録を持っているか」が精度に最も効きます。
モデルどうしの答えが食い違っているときは、その分だけ精度を下げ、予測レンジを広げます。
精度を上げるための具体的な助言はホーム画面に出ます。

## 配色とデザインの方針

このアプリは**グラウンドで日光の下に見る**ので、読みやすさを優先しています。
色は [`lib/theme.ts`](lib/theme.ts) に集約。

### 文字は 4.5:1 を下回らせない

補助テキストの色が薄すぎたので、文字色の階調を一段ずつ濃くしました。

| | 変更前 | 変更後 |
|---|---|---|
| `text` | `#171a21` | `#111827`（16.9:1） |
| `textSub` | `#6b7280`（5.7:1） | `#475569`（8.3:1） |
| `textFaint` | `#9aa4b8`（**2.6:1**） | `#5b6779`（5.6:1） |

`textFaint` は 10〜11px の文字に多く使われていたので、ここが一番効きます。

塗りの上に白文字を置く箇所も見直しました。ブランド色の `accent`（`#e8541f`）は
白文字だと 3.4:1 しかないため、塗り用に濃い `accentStrong`（`#c2410c`、5.0:1）を分けています。

### 強度の色は「温度」で並べる

変更前は「800mレースペース＝赤」のあとに「スピード＝橙」が来ていて、
**色を見てもどちらがきついのか分からない**状態でした。
楽→きつい が色の温度で上がるように並べ替えています。

| 段階 | ゾーン | 色 |
|---|---|---|
| 1 | ジョグ | 灰 `#4b5563` |
| 2 | 閾値走 | シアン `#0e7490` |
| 3 | VO2max | ティール `#0f766e` |
| 4 | 1500mペース | 黄土 `#a16207` |
| 5 | 800mレースペース | 橙 `#c2410c` |
| 6 | スピード | 赤 `#b91c1c` |
| 7 | スプリント | 赤紫 `#86198f` |

あわせて**色チップの中に段階の数字（1〜7）を入れました**。
色覚特性や日光の反射で色が判別しづらい場面でも、順序が分かります。
7色すべて白文字で 4.5:1 以上を確保しています。

### 数字には意味を添える

「精度 60%」だけでは良いのか悪いのか判断できないので、
**「精度 ふつう（60%）」**のように言葉を添えています。

## ペースゾーン

すべて 800m レース速度（v₈₀₀）に対する比で定義しています。

| ゾーン | v₈₀₀ 比 | 用途 |
|---|---|---|
| ジョグ | 0.44–0.52 | W-up・回復・土台づくり |
| 閾値走 | 0.68–0.74 | 乳酸を処理する力を上げる |
| VO2max（3000mP） | 0.78–0.84 | 最大酸素摂取量を上げる |
| 1500mペース | 0.86–0.91 | スピード持久の中核 |
| 800mレースペース | 0.98–1.02 | レース感覚とリズム |
| スピード | 1.03–1.08 | 乳酸耐性・ラスト勝負 |
| スプリント | 1.09–1.15 | 最高速度・神経系 |

## iPhone のホーム画面に追加する（PWA）

iPhone に「アプリとして」入れるには Apple Developer Program（年 $99）が必要ですが、
**Web 版をホーム画面に追加すれば無料**でアイコン付き・全画面で使えます。

そのための設定は済んでいます:

- [`public/index.html`](public/index.html) … 全画面化・ホーム画面アイコン・ノッチ対応のメタタグ
- [`public/manifest.json`](public/manifest.json) … アプリ名・テーマ色・アイコン
- `public/` の中身は書き出し時にそのままルートへコピーされます

### GitHub Pages で公開する（設定済み）

[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) を入れてあるので、
**`main` に push するだけで自動的に公開されます**。手元で書き出す必要はありません。

初回だけ GitHub 側の設定が必要です。

1. GitHub で `track800` という名前のリポジトリを作る
   （GitHub Pages を無料で使うには **public** にする必要があります）
2. push する

```bash
git remote add origin https://github.com/<ユーザー名>/track800.git
git push -u origin main
```

3. リポジトリの **Settings → Pages** を開き、**Source** を **「GitHub Actions」** に変更
4. Actions タブでビルドが終わるのを待つ（2〜3分）
5. `https://<ユーザー名>.github.io/track800/` が公開される

以降は `git push` するたびに自動で更新されます。

**サブパス配信について**: GitHub Pages は `/track800/` の下で配信されるため、
[`app.config.js`](app.config.js) がワークフローから渡されたリポジトリ名を受け取って
`baseUrl` を組み立てています。`public/` の中身は Expo によるパス書き換えの対象外なので、
`index.html` と `manifest.json` の参照は相対パスにしてあります。

### ホーム画面に追加する

1. iPhone の **Safari** で公開 URL を開く
2. 下部の **共有ボタン**（□に↑）→ **「ホーム画面に追加」**

> Chrome ではなく Safari で行ってください。iOS ではホーム画面への追加は Safari のみです。

ホーム画面に追加した Web アプリは、iOS の「7日間使わないとデータを消す」制限の対象外なので、
記録は消えずに残ります。

## アイコン

ネイビー地にオレンジのトラック（走路）、中に「800」。
画像編集ソフトを使わず、[`scripts/make-icons.js`](scripts/make-icons.js) が
符号付き距離関数で図形を描いて PNG を書き出しています（依存パッケージなし）。

```bash
npm run icons
```

- `assets/icon.png` … 1024px。iOS とストア用
- `assets/adaptive-icon.png` … Android のアダプティブアイコン。外周が切り取られるので図柄を中央 62% に収めてある
- `assets/favicon.png` … 16px 前後まで縮むため「800」は省き、マークだけにしてある
- `public/apple-touch-icon.png` … iPhone のホーム画面用（180px）

色や形はスクリプト上部の定数（`TRACK_R` / `GLYPH_H` / `COLOR_TRACK` など）で調整できます。

```
screens/
  HomeScreen        推定タイム・根拠・ペース設定・換算タイム
  LogScreen         練習の記録と一覧
  SuggestScreen     メニュー提案（1回分 / 1週間）
  MenuLibraryScreen 自分のメニュー一覧と共有コードの取り込み
  MenuDetailScreen  メニュー詳細・共有・編集・削除
  MenuBuilderScreen メニューの作成と編集
  SettingsScreen    プロフィール・自己ベスト・データの書き出し
```

## あとからサーバーを足す場合

保存まわりは [`lib/storage.ts`](lib/storage.ts) と
[`lib/AppContext.tsx`](lib/AppContext.tsx) に閉じています。
公開メニューの検索や端末間同期が必要になったら、この2つを差し替える形で足せます。
